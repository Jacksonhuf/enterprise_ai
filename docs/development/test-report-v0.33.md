# 第三十三轮：MySQL失败观测记录定向追加

基线：PR #29已合并main，b19761bee46b22b5cf17b560eafd34784753f6dd。部署方案暂不改变，继续现有Go/Vue/MySQL开发。

## 实现

MySQL v2的失败记录使用专用事务，将失败审计追加到关系表、OPEN异常通过JSON_ARRAY_APPEND追加到body.exceptions。exceptions缺失/null时只初始化该路径；已有数组和数组元素中的未知字段保留。其他应用/会话/配置及未知嵌套值不重新序列化。普通独立审计（例如模型连接测试记录）也接入审计专用事务，避免在记录HTTP异常前先经过聚合重写。

保留既有追踪ID、模式化接口路径、错误脱敏、企业归属和版本字段；拒绝无审计的异常、企业不匹配、无id/版本或非OPEN状态、不可序列化异常。4xx只记审计，5xx未取消请求才生成异常；原请求取消时仍可用独立5秒上下文记录canceled审计。记录仍为既有best-effort语义，写库失败不递归生成异常、不自动重试未知提交。

沿用状态行FOR UPDATE以保持序号和既有业务事务顺序，不获取Store.mu。没有新表、schema_version或HTTP参数；v1、其他存储、相关顶层大小写别名回退原实现，异常状态迁移尚未改为定向SQL。

## 验证

新增3项顶层Go测试，总计115项：

- 审计和异常同事务、保留已有异常与其他域的未知大整数；重复审计批次全部回滚；用隔离测试库CHECK约束让异常UPDATE在审计INSERT之后失败，确认两者均回滚；无审计/跨企业/无效JSON拒绝及旧别名回退。
- 两个Store并发记录失败，两次审计与异常均保留且request_id对应；null容器初始化、其他域保留及取消不提交。
- 真实HTTP v1/v2模型连接失败，既有模型审计与HTTP失败审计均存在，异常关联真实request_id；用户伪造追踪ID不接受，接口路径不含实际对象参数；v2其他业务嵌套字段保留，重开后关联仍在。

本地存储/API包测试通过，未配置真实MySQL时数据库用例跳过。正式数据库结论以PR最新完整CI为准；继续运行竞态检测、MySQL/PostgreSQL、接口契约、运行恢复/迁移命令、57项前端与浏览器业务回归。

## 边界

异常仍存于现有状态行中的JSON数组，不是独立异常关系表；保存仍有数据库全局状态行锁，无吞吐基准。此轮不改部署架构，不宣称完成关系表迁移、生产身份、可靠发件箱或真实A–E联调。
