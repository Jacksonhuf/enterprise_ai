# 第三十一轮：MySQL配置定向保存

基线：PR #27已合并main，612e9231092ba61902b90b7ddbf8e80bfc21dc8a。

## 改造

个人资料、通用偏好和公共配置的MySQL v2保存使用独立的定向SQL事务。读取当前配置、获准的旧配置回退值、版本及必要结构元数据，不读取整个body到Go；JSON_SET只写选中配置与版本路径，审计用既有关系表同事务追加。无变化保存直接提交只读结果，不执行UPDATE或新增审计。

服务端仍负责生成租户/用户/分区键与旧键访问条件、参数验证、初始版本摘要、expected_revision核对和审计内容。SQL路径和值均作为参数绑定，带引号/反斜线的键也按JSON字符串编码。缺失/null的配置容器显式初始化为对象，不删除其他域。已知的settings/setting_revisions/audit顶层大小写别名在回调前回退原实现，保持Go解码兼容。v1、JSON、SQLite、PostgreSQL使用原路径；没有新增HTTP接口或数据库schema。

此路径不获取Go Store.mu且不写缓存，读取继续以数据库为准。数据库仍锁定同一状态行，不能称作取消全局写锁或支持线性横向扩展。MySQL内部JSON更新与日志成本仍受实际数据库实现和负载影响，尚无性能基准。

## 验证

新增4项顶层Go测试，总计109项：

- 定向写入与审计同事务，配置容器null初始化、含引号/反斜线键、保留其他域中的未知嵌套值与大整数、无变化/失败/重复审计回滚及取消。
- 旧配置值读取、旧键保留、v1及顶层大小写别名在回调前回退。
- 真实HTTP v1/v2对照：旧资料迁移、规范化、初始版本、过期版本409、相同内容保存不重复审计、清空恢复默认资料、用户/企业隔离、公共配置权限与旧别名回退。
- 双宿主同版本并发修改只有一个200、一个409、一次审计，并保留应用对象中不属于配置域的未知属性。

本地存储/API包测试通过，数据库测试未配置MySQL时跳过。最终真实数据库结论以PR完整CI为准；继续回归竞态检测、MySQL/PostgreSQL、接口契约、运行/恢复/迁移命令、57项前端测试及浏览器业务流程。
