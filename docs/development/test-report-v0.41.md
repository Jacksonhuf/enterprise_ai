# 第四十一轮：授权审阅与发布后访问闭环（2026-11-17）

PR #37 已合并 main：5c29b5edffd4aa0c16c63515d5e12eb35ca7d5d7。本轮继续复用 Cognara/TDesign 和现有授权接口，不新增权限模型、HTTP路由、字段或数据库变更。

## 实现

- 新增授权先捕获主体、资源、操作和数据范围，展示审阅内容，再确认提交。审阅期间锁定输入，可显式返回修改。
- 保存与撤销采用同一状态控制器：捕获固定目标/载荷、序列化请求、校验成功响应；页面销毁后忽略迟到响应。
- 网络/超时/5xx/无效成功响应及权限变化后阻止直接重试，要求重新加载授权列表核对。重新加载失败不解除阻断；原服务端授权去重与撤销幂等保持。
- 撤销只作用于捕获的本条授权；其他有效授权仍可允许访问。用户应用使用权不替代应用自身能力调用权。
- 授权列表、审阅和撤销确认显示当前企业已加载应用名称；应用目录晚响应不会更新销毁页面。

## 验证设计

新增6项前端状态回归：载荷/展示快照与字段白名单、重复请求、目标固定与晚响应、未知结果/无效响应、可修正错误、权限/版本失败阻断。

新增2项Go HTTP回归：从模板创建并发布副本后，用户默认不可见/不能新建会话；管理员授权后可见/可新建会话；重复授权不重复审计；撤销后受限但原应用不受影响。另验证应用服务调用授权与用户应用使用授权独立。

Chromium扩展：模板副本首次发布 → 用户目录初始不可见 → UI选择用户/新应用 → 审阅并确认授权 → 普通用户可见并进入 → UI撤销 → 普通用户目录移除副本且原应用保留。继续原有聊天、契约、模板、恢复、发布、偏好和账户隔离回归。

## 证据与边界

本轮本地执行环境不可用，没有本地通过结论。预计平台顶层Go测试定义132项、前端90项；最终以对应PR最新提交的完整CI记录为准，包括真实MySQL/PostgreSQL、契约、四种存储运行/恢复/迁移、类型/构建/预算及Chromium。
