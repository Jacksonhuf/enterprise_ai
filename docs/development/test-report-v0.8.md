# 第八轮：授权完整性与应用选项

日期：2026-11-16。基于已整合PR #2/#3的main（5e6e178）。

## 改动

授权创建在同一Store事务内校验主体和资源归属、检查相同有效授权、写入授权与变更审计。应用身份必须属于当前企业；验证用户也按企业归属检查。主体类型、主体ID、资源类型、资源ID、操作、数据范围和企业完全相同时，返回原有效授权，不新增授权或authorization.grant事件。

重复撤销已撤销授权保持成功，不重复产生authorization.revoke变更事件。撤销后重新授权创建新的记录与审计，保留历史；不静默激活旧行。现存历史重复授权不会自动合并，仍须分别核对撤销；不同主体/操作的授权保持独立。请求级失败/访问日志和授权状态变更审计不同，此处只对后者去重。

授权表单完整读取应用目录分页，按应用ID去重，并允许搜索已加载选项。任何后续页失败时不提供不完整选项，显示重试并阻止保存；游标循环明确失败。提交中不重复发送保存请求。复用原有TDesign表单和抽屉。

## 接口兼容

POST /api/v1/cognitive/governance/grants 参数、返回Grant对象及200状态不变；相同有效授权返回同一个grant_id。校验失败仍400，非管理员403。DELETE /api/v1/cognitive/governance/grants/{id} 对存在的本企业已撤销记录仍200，但无重复状态变更审计；不存在/其他企业记录404。

## 验证清单

新增4项Go测试，合计50项：跨企业主体/资源拒绝、已有授权复用、12路并发去重与撤销后拒绝访问/重新授权、两个真实PostgreSQL连接与API宿主下的并发去重。新增3项前端测试，合计16项，覆盖102个应用跨页加载、重叠去重、后续页失败与循环游标。
