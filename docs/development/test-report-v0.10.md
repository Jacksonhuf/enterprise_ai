# 第十轮：治理台检索、筛选与稳定分页

日期：2026-11-16。基于已合并PR #5的main（f422e5b）。

## 交付

审计、异常、用量和资源授权列表支持服务端检索、可追加分页与筛选。审计可按request_id、execution_id、用户/应用/资源标识和操作检索，支持结果及时间范围；异常支持处理状态与时间；用量支持单位与时间；授权支持有效/已撤销状态。日期范围使用TDesign日期控件并转换为真实时间，边界包含起止时点，不用时间字符串的字典序比较。

分页使用最后一条已返回记录的ID定位，绑定企业、列表类型和规范化筛选条件。每次请求重新执行管理员检查与企业隔离；游标是定位信息，不是授权凭据，也不是加密令牌。追加新审计记录不会导致旧页位移。筛选改变、定位记录被移出筛选结果或游标无效时400并要求刷新；客户端切换条件会从第一页重新加载。列表显示“已加载”，不冒充总量统计。

按接收顺序由新到旧排列，时间筛选依据occurred_at，不声称是按业务发生时间重排。不存在时间字段的授权列表拒绝时间筛选。不同用量单位分别筛选，不混加调用、词元和时长。原静态用户/角色/状态页面保持原结构。异常状态变更及授权写入接口不变。

## API兼容扩展

GET /api/v1/cognitive/governance/{section}：audit/exceptions/usage/grants新增可选query（最多256字符）、limit（1–100，默认20）、cursor；返回保留items/sampled_at/mode，增加next_cursor（末页null）。

- audit：outcome可为success/accepted/denied/failed/partial/canceled。
- exceptions：status可为OPEN/ACKNOWLEDGED/RESOLVED。
- grants：status可为ACTIVE/REVOKED。
- usage：unit可为CALL/TOKEN/MILLISECOND。
- audit/exceptions/usage：from_time/to_time可分别省略，提供时为RFC3339时间，起点不得晚于终点。

不适用的筛选参数、非法值、改变筛选后复用游标返回400；非管理员仍403。分页从原全量响应改为默认20条，调用方需按next_cursor继续读取。

## 测试

新增6项Go回归，合计59项：关联编号/大小写检索、真实事件接收后小写t/z时间戳的筛选、时区与包含边界、45条记录分页及并发追加、游标绑定和筛选变化、租户与管理员隔离、授权/异常状态筛选、30条用量按单位分页。

新增3项前端测试，合计23项：日期时间转换、各列表适用条件、游标透传与无效时间范围。继续复用已有分页竞态、授权失败清空与失败重试测试。完整检查沿用真实PostgreSQL、Go race、HTTP契约及三种存储的编译程序运行验收、类型检查和构建。实际通过状态以对应提交的CI为准。

## 边界

当前存储仍是聚合验证适配，服务端在内存中筛选，不代表生产索引/大规模检索方案。游标不冻结状态快照，记录状态变化时可能需要刷新。没有新增统计总量、导出文件、生产SSO、真实A–E能力或全量视觉验收。
