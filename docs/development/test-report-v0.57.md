# 第57轮：R05-B schema3根域通用writer

基线PR54。schema3下会话、授权、设置、用量、回执与异常仍由`cognara_fg_state.body`根域承载，旧锁定writer在schema3下拒绝写入。本轮新增内部根域writer补齐该缺口，持有State屏障并在提交前经关系读取器完整重组校验。

语义：锁定State行（要求schema3），经关系读取器重建完整State后执行回调。回调改动应用（含新增/删除）或检查即拒绝，必须走专用关系writer，根不重新成为应用/检查的第二权威。审计沿用schema2规则：业务模式回调不加载历史、仅可新增事件，按当前最大序号追加；完整模式可追加但不得改写既有事件。写回时根不含apps/checks键，未知根级扩展字段（含大整数）按原文保留。

真实MySQL 8.4专项（本地8.4.9实例）：业务模式写入会话、设置与审计同事务提交且回调看不到审计历史；根不含apps/checks、扩展字段精度保留、应用投影不变；完整模式改写既有审计被拒、追加成功；修改应用草稿、注入应用、注入检查均返回专用错误，回调报错不落库，状态逐字节不变；两连接并发追加授权与一路专用草稿writer并发执行，三者均提交且无丢失更新；审计触发器故障时整体回滚；关闭连接重开读取一致。另做三项变异验证：取消应用/检查守卫、取消根扩展保留、以直接插入替代审计不可变追加，均被测试捕获。

仍未接HTTP或启动，旧Store在schema3下继续拒绝锁定写入。保留State锁，非容量验收。下一步为业务入口按域切换到关系/根writer的适配层，以及原文布局无损快照（C）与显式apply（D），R05-B保持开发中。完整CI见PR。
