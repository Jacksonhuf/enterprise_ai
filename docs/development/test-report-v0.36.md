# 第三十六轮：MySQL用量列表按租户分批读取

基线：PR #32已合并main，4ff348a4a6578dec8e94c4a1646cef3942370e79。部署方案不变。

## 实现

异常与用量共用只读治理数组查询仓储，只允许内部固定exceptions/usage枚举进入SQL路径；用户不能指定任意JSON路径。MySQL v2用量列表通过JSON_TABLE按完整字符串tenant_id过滤、接收顺序倒序分批投影，每批最多200候选；Go继续原unit/query/time筛选和ID游标锚点复核。原exceptions仓储入口及游标错误标识保留，既有异常列表测试完整回归。

保留v1游标和event_id/grant_id/id稳定标识优先级；单位或列表变更使游标失效，新追加记录不进入旧锚点之后的页。只读RepeatableRead、不获取Store.mu或FOR UPDATE；请求取消、错误返回及旧版本/相关大小写别名回退保持。无HTTP参数、表结构或schema_version变化。

用量事件接收、摘要/Receipt去重、业务执行和入账逻辑没有改动。投影保留数据库已有JSON数字，不再次经float64序列化；这不表示修复既有事件接收/其他聚合写入中的全部数字精度问题，也不等同完整财务记账。

## 验证

新增3项顶层Go测试，总计125项：

- 同时持有本地互斥锁和数据库未提交写锁，返回已提交用量；排除外企/数字/尾空格企业标识，保留已有大整数，不读错异常数组、不修改body，旧版本/别名回退及取消。
- 431条本企业用量加外企数据，逐页对比v1/v2数据与游标，覆盖CALL/TOKEN/MILLISECOND、中文/稀疏搜索、跨200批次、纳秒/小写时间/0001年、无结果、grant_id旧标识及迁移前游标。
- 实际内部用量回调的ACCEPTED/DUPLICATE、新事件追加及旧页连续性；查询/拒绝请求不改变用量条数和回执；普通/外企用户403、单位/跨列表/非法参数或失效锚点400、数据库关闭503。人为改变锚点单位仅用于验证重筛，不表示开放用量编辑能力。

本地存储/API测试结果与完整CI记录见PR；缺少MySQL配置时本地数据库用例跳过，正式数据库结论以最新CI为准。继续竞态检测、真实MySQL/PostgreSQL、接口契约、运行/恢复/迁移命令、57项前端与浏览器回归。

## 边界

数据库仍扫描JSON数组并从当前快照定位ID锚点，不宣称租户索引、恒定成本分页、独立用量关系表、吞吐基准或生产计费能力。业务关系表、数据库写锁拆分及生产联调仍待完成。
