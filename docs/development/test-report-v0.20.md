# 第二十轮：审计关系表与显式迁移

日期2026-11-16，基于PR #16已合并main（94ee4d7）。

新增InnoDB审计表cognara_fg_audit，独立租户/事件复合主键、稳定序号唯一键、租户序号索引，以及UTC DATETIME(6)时间/操作人/动作/资源字段（原始纳秒时间保留在事件JSON，非法时间拒绝迁移）和事件JSON。SQL随Go代码嵌入并纳入版本控制。显式cognara-migrate-audit --apply迁移将v1聚合审计写入关系表，同时移除聚合审计字段并把状态版本切为2；插入失败时审计行与状态版本一起回滚。DDL可能留下空表，不自动删表。重复运行只验证v2，不重复导入。

迁移前必须停止目标应用、导出并核对v1快照，并使用独立MySQL备份保留原库。新程序同时读取v1/v2；v2读取在同一只读一致性事务内重组状态与审计，更新仍持有状态行锁，业务字段和审计追加同一事务提交。审计只追加，修改/删除旧事件或重复租户事件键将拒绝并回滚业务更新。审计实际表结构、引擎与唯一索引不兼容时拒绝访问。迁移保留其他聚合未知字段，未知审计字段则拒绝迁移，避免静默丢失。

新增3项顶层测试：迁移/重复执行/重开/追加与重复事件事务回滚/防篡改；源重复事件导致迁移失败且v1数据及空目标不变；两个MySQL API宿主在v2审计下并发重命名、审计仅一次且撤权生效。原v1 API测试保持。CI包含迁移入口的编译检查和真实MySQL事务测试。

本地包测试通过，真实MySQL验收以PR CI为准。本轮不是全部生产表交付：应用/会话/授权等仍是聚合JSON，全局状态锁、全量审计重组和内存筛选仍存在，不宣称数据库分页或横向扩展已完成。现有快照导出/导入只支持v1，v2会明确拒绝，不能拿v1快照替代v2关系表备份。回滚需停机恢复迁移前独立库及匹配程序，不提供自动降级；原v1-only程序不能访问v2。既有HTTP契约不变。
