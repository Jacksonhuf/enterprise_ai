# 第三十七轮：历史发布恢复为草稿

## 变更与接口

基于已合并 PR #33（main：c9882d69ff0df94f9b7337cd72c4f1fb2c6aeb69），在应用详情发布配置抽屉增加“恢复为草稿”。确认框展示当前草稿到历史配置的逐项变化，沿用 Cognara 主题与 TDesign 组件。

复用 PUT /api/v1/cognitive/apps/{app_id}，请求为历史 config_snapshot 的四个配置分组及当前 expected_draft_revision；没有新增 HTTP 路由、发布协议或数据库字段。成功进入编辑器；必须重新执行现有 release-checks、releases 流程才影响线上版本。历史快照及当前发布指针不因恢复而改变。

恢复操作绑定确认时的草稿版本，克隆配置，阻止重复提交。409、网络失败、超时、5xx 或无效成功响应后阻止直接重试，要求重新加载核对。组件销毁后忽略迟到响应；请求超时不代表服务端撤销。

## 回归设计与验证

- 新增 5 项前端测试：确认快照/CAS、跨应用及无差异拒绝、重复提交及迟到响应、冲突及不确定结果、无效成功响应。
- 新增 Go HTTP 回归：发布修改版后恢复历史配置；确认当前发布和历史记录不变；旧 CAS 被拒绝；旧发布检查不能用于恢复后的草稿；新检查正常发布新版本。
- Chromium 流程：准备不同草稿 → 发布历史抽屉 → 差异确认 → 恢复 → 编辑器及刷新 → 核验草稿、发布指针及历史快照。
- 本地前端 62 项通过，生产构建、包预算通过。入口 248200 字节，总 JS 731017 字节。
- 类型检查采用本项目 CI 的 tsconfig.cognara.json；上游全项目 npm run type-check 本地达到默认 Node 堆上限，不能计为通过。
- 完整 Go 竞态、真实 MySQL/PostgreSQL、契约、运行/迁移/恢复及 Chromium 结论以本轮 PR 的最新提交 CI 为准；本地无数据库环境不能代替数据库 CI。

## 边界

这是历史配置恢复为草稿，不是直接将线上指针回滚。恢复前未重新验证历史引用是否仍有效；恢复后的发布检查负责验证模型、资产、服务和权限。正式 A–E、真实提供方、SSO、关系表及生产部署仍待验收。
