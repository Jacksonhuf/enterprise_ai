# 第二十三轮：MySQL v2逻辑快照与空库恢复

日期2026-11-16，基于PR #19已合并main（20da7c1）。

导出命令自动识别v1/v2。v1原始JSON不变；v2输出format=cognara-fg-snapshot、schema_version=2、state、audit封套。业务状态与全部审计在同一只读REPEATABLE READ事务中读取，检查审计序号及租户/事件关联，保留未知状态字段和未知事件JSON字段。大小上限64MiB、深度上限256、0600文件和禁止覆盖继续保留；报告新增源版本和审计数量，SHA摘要覆盖最终整个文件。

导入必须显式指定源版本和摘要。v2验证封套、审计身份/时间、重复事件、业务绑定后才连接目标；目标必须没有状态及审计行，业务状态和审计同事务插入。插入失败回滚数据，DDL可能留下空表，不自动删表；已有目标及孤立审计均拒绝接管。提交不明确时检查目标，不自动重试。v1快照继续兼容，不能把v2封套按v1导入。

新增3项顶层测试：真实MySQL含Unicode ID/0001年时间/未知字段的v2导出→编译导入命令→重开→再次导出逻辑核对，已有目标和孤立审计拒绝且无部分状态；并发写入时8次快照保持业务计数与审计条数同一事务视图；错误/重复审计封套拒绝。原v1快照和四种存储、API/前端/契约/浏览器回归继续执行。

本地包测试通过，但无MySQL实例，真实结果以PR CI为准。该工具是聚合业务状态及关系审计的逻辑备份，不包含外部证据、数据库账号/权限、其他专业存储或全部部署配置，不提供在线增量或时间点恢复。恢复与迁移需在副本核对并保留独立完整数据库备份。本节替代早期“新工具只支持v1”的限制；旧版工具仍不支持v2。其他生产关系表和全局状态锁尚待演进。
