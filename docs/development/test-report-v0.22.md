# 第二十二轮：业务读写只处理本次新增审计

日期2026-11-16，基于PR #18已合并main（1819aef）。

增加ReadOperational、UpdateOperational及其Context变体。MySQL v2业务读取不重组历史审计，写入回调的Audit仅是本次新事件缓冲；同一状态行锁下查询审计唯一顺序索引的尾值，再插入新增事件并提交业务JSON。清空缓冲不删除旧记录，重复事件或回调失败时业务和本次插入一起回滚。最大序号溢出明确拒绝。API中的状态读取与修改使用新接口；审计历史使用前轮分页查询。

保留原Read/Update接口用于全量核对、兼容与迁移，原路径仍验证旧审计不可改删。JSON/SQLite/PostgreSQL和MySQL v1保持原聚合审计行为；新的缓冲语义仅适用于MySQL v2，新增业务回调不能依赖Audit历史。其他状态字段与HTTP契约未变。

新增2项真实MySQL顶层测试：310条旧审计下的新事件缓冲、普通读取不暴露历史、重复事件失败同时回滚业务字段、清空缓冲不删除历史；两个宿主各12次并发计数修改/审计追加，最终计数24、审计24且取消请求不写入。现有MySQL v2 API并发/授权测试继续执行。本地相关Go包通过，真实数据库结果由PR CI确认。

本轮移除普通业务路径的全量审计读取，但仍保留全局状态行锁、聚合JSON及其整体序列化；不是完成所有生产表或无锁扩展。新路径只验证所写事件和结构，不扫描整个审计表验证历史完整性；专用核对接口仍可全读。API权限和业务/审计事务边界保持。
