# 第三十九轮：发布前变更审阅（2026-11-17）

## 基线与实现

PR #35 已合并 main：e81d7c7beb5c966b70416e942e899e9649a5de94。本轮继续完善应用发布确认流程，沿用 Cognara/TDesign 抽屉及已有配置差异函数。

确认抽屉增加当前发布到本次检查草稿的变更表、基线发布版本与草稿版本。首次发布展示全部九类配置项；配置未变化时说明确认仍会生成新发布版本。多行提示词与业务文本使用 Vue 插值展示，不作为 HTML 执行。

审阅捕获字符串和版本元数据，不引用可编辑草稿。缺少当前发布快照、重复发布标识或快照属于其他应用时拒绝检查并要求重新加载。检查期间已知草稿或发布指针变化时丢弃结果。保存、加载、页面失效及发布结束清理审阅。原有过期、脏草稿、用户与版本绑定继续生效。

## 接口与边界

继续使用 GET /api/v1/cognitive/apps/{id}、PUT 草稿、POST release-checks 及 POST releases；没有新增 HTTP 路由、请求字段、数据库字段或 A–E 能力。确认发布仍提交原 check_id、expected_draft_revision、expected_current_release_id、release_note。

审阅是加载/检查时的快照；其他客户端稍后发布由服务端 CAS 拒绝，不承诺实时推送。历史发布不可变，下一轮读取新发布的既有语义不变。配置克隆/归一化提取为共用纯模块，保留原导出兼容入口，避免循环依赖。

## 验证设计

新增 8 项前端测试：
- 当前发布对比、无可变引用、首次发布九类配置。
- 缺失/重复/跨应用/不完整基线拒绝。
- 服务版本与问题顺序保留、资产引用排序不误报。
- 审阅与检查版本绑定，保存/重载/发布后清理。
- 检查期间发布指针变化、未知发布结果与页面失效不启用旧确认。

扩展 Chromium：恢复草稿后查看无差异提示 → 取消 → 修改业务描述 → 保存并检查 → 核对差异/版本 → 确认前线上及历史不变 → 真实发布 → 核对新版本和旧快照。

继续全套 Go 竞态、真实 MySQL/PostgreSQL、HTTP 契约、四种存储、恢复/迁移、前端类型/构建/预算及浏览器回归。
