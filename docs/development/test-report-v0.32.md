# 第三十二轮：MySQL配置与资料定向读取

基线：PR #28已合并main，7ee71f6d8184ef878d220e37934750dd718a79a4。

## 实现

MySQL v2的GET settings/{section}和GET /me显示名称通过配置仓储读取单配置、获准旧值、版本和必要结构元数据，不把整份应用/会话状态传回Go。使用只读RepeatableRead事务，不获取Store.mu，不使用FOR UPDATE。配置值与版本来自同一SELECT/快照，不读尚未提交的保存。5秒超时及请求取消继续传递。

保存与读取共享投影解码，避免两套旧键、canonical null、版本和大小写别名逻辑分叉。租户/用户/分区键和旧键访问条件仍由API产生，HTTP授权边界不变；显示名称不能改变身份/角色。v1、其他数据库、旧settings/setting_revisions/audit顶层别名回退原Operational读取，不宣称本轮改变这些回退路径的锁或错误行为。

定向查询、schema检查或提交失败直接返回原API错误信封503，不回退为空配置或默认资料。不新增HTTP参数、数据库表或schema_version。配置保存事务和4xx审计专用追加保留。

## 验证

新增3项顶层Go测试，总计112项：

- 数据库事务锁住并修改配置但尚未提交，同时锁住Store.mu，定向读取仍在超时内完成，返回旧的已提交值与r1版本；回滚后body不变。
- v1/旧别名回退、获准旧键读取、无旧键时不泄漏、canonical null优先、带引号/反斜线键、请求取消和未知版本拒绝。
- 真实HTTP保存后GET与返回revision一致、/me显示名称和身份保持；关闭数据库后profile/general/me均返回503错误信封而不是默认值200。

原v1/v2配置HTTP兼容和双宿主CAS测试继续运行，覆盖初始版本摘要、清空、无变化保存、用户/企业隔离和公共配置权限。本地存储/API测试结果见PR；未配置真实MySQL时本地数据库用例跳过，数据库结论以完整CI为准。CI继续竞态检测、真实数据库、接口契约、运行/恢复/迁移、57项前端测试与浏览器回归。

## 边界

已优化的是配置/显示资料读取，不是整个Store的读取或全平台无锁化；MySQL二进制JSON内部访问成本与实际负载仍需基准验证。配置尚未拆成独立关系表，保存仍锁定状态行，其他业务表/5xx异常聚合写入、生产身份及A–E联调仍待推进。
