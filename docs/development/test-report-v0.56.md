# 第56轮：R05-B发布检查与发布事务writer

基线PR53。新增两条内部schema3原语，均持有State屏障并在提交前完整重组校验。

检查记录：可信调用方在完成引用校验后传入租户、操作人、期望草稿revision、validation_id与有效期。锁定草稿行核对revision；拒绝外租户、旧revision及已过期时间。缺失或null的检查容器按旧写入语义物化为对象。与现有HTTP路径一致，记录检查不写审计。

发布：锁定应用头、草稿行与检查行。检查必须属于本应用、本操作人、当前草稿revision且未过期；期望当前发布按旧接口CAS（含首次发布的空指针）。快照取锁定草稿原文，保留未知扩展与大整数/高精度数值；按序号追加，不改写历史发布；更新当前发布指针，null发布容器转为数组；同事务删除检查并写入`application.publish`审计（含client与request标识）。发布不改变草稿revision和应用更新时间，与旧路径相同。

真实MySQL 8.4专项（本地8.4.9实例）：外租户/旧revision/过期检查拒绝；null容器物化；保存草稿后旧检查不可用；外租户、他人检查、旧revision、当前发布不符与首次发布误判均拒绝且不消耗检查；双连接用同一检查并发发布仅一成功，另一方得到检查失效；历史发布逐字节等价、新快照扩展精度保留、序号正确；先检查后改草稿再发布被拒绝；1.2秒有效期过期后拒绝；审计触发器故障时整体回滚、检查保留，移除故障后可用同一检查发布；null发布容器首次发布；关闭连接重开后读取一致。另做三项变异验证：不删除检查、改用类型化快照、不绑定检查revision，均被测试捕获。

仍未接HTTP或启动，schema3不开放。检查/发布无跨重试幂等键，提交结果未知时不能盲重试。保留State锁，非容量验收。其余业务writer、原文布局无损快照（C）及显式apply（D）未完成，R05-B保持开发中。完整CI见PR。
