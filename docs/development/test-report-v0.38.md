# 第三十八轮：认知服务契约详情

## 基线和变更

PR #34 已合并 main（b01ea51d2c5761f3d8540225756f2bcd8edd2153）。本轮继续完善应用开发者引用服务前的契约审阅，沿用 Cognara/TDesign 详情抽屉，增加输入/输出切换及契约修订展示。

读取既有 GET /api/v1/cognitive/selectors/services 中的 service_version、contract_revision、input_schema、output_schema。无新增 HTTP 路由、请求参数、数据库字段或模型工具。服务发现授权和运行授权仍独立。

## 阅读能力和限制

- 展示嵌套对象、数组元素、父对象内必填项、枚举、数值/长度/数组等约束、描述及原始定义。
- 字段路径使用 JSON Pointer 转义；不推断未声明的类型、输出字段或必填项。
- $ref 保留原文，不请求外部地址；组合、条件及元组约束明确引导阅读原始定义。此组件不是 JSON Schema 校验器。
- 表格最多 200 行、8 层展开；原始文本最多 64000 字符；超出时显示截断提示。完整约束仍以目录原始契约为准。
- 当前供应链验证服务输出只有 {"type":"object"}，页面明确提示缺少具名字段明细，不据示例计算结果补造输出契约。
- 布尔 Schema、缺失/无效定义、循环对象等阅读边界已测试。Vue 插值显示描述和原始文本，不解释为 HTML。

## 本地验证

- 新增 6 项前端契约投影回归；共 68 项前端测试通过。
- 新增 Go HTTP 回归：工程师/管理员可以读取准确版本、修订、输入上下界/必填约束和原样输出；普通用户/外部身份拒绝；阅读不产生会话、执行回执或用量。
- Go 竞态测试及四个运行命令包通过；本地未配置数据库和编译运行二进制所需环境的特定集成用例按原条件跳过，不能视为真实数据库验收。
- 补装与 CI 一致的 jsonschema 格式依赖后，校验本地 178 组实际内部 HTTP 契约通过，另 2 个非法请求正确 400。本地跳过数据库用例，因此组数不能与完整 CI 混用。
- Cognara 专用 TypeScript 检查、生产构建、包预算通过：入口/最大块 248305 字节，总 JS 736279 字节。

## 完整验收

新增 Chromium 流程：打开服务详情 → 输入约束 → 输出缺项提示 → 查看原始定义 → 切回输入 → 切至资产详情，确认组件不串页。继续上一轮恢复草稿、聊天、角色导航、偏好持久化等业务回归。

真实 MySQL/PostgreSQL、全部契约、四种存储运行/恢复/迁移以及浏览器结论以本轮 PR 的最新提交 CI 为准。页面功能验证不等同于全部 Figma 逐屏视觉验收；真实 A–E 输出契约完整性仍需对方提供正式定义后联调。
