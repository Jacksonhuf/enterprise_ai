# 第三十轮：MySQL审计结构语义检查

基线：PR #26已合并main，9f06587cbf4a7a5e6b976f25f0091074fd02a803。

## 问题与实现

原审计表检查只核对索引名、列顺序和唯一性，不能识别前缀索引；前缀主键可能让两个完整ID不同的合法事件发生唯一冲突。列类型检查也未验证字符集，varchar(255)使用latin1/utf8mb3时不支持契约允许的中文或四字节字符。

检查现要求既有审计索引均为无SUB_PART前缀、无表达式、可见的BTREE，仍保留索引列与唯一性检查。actor_id/action/resource_id要求utf8mb4；比较身份仍使用既有VARBINARY主键，不根据文本排序规则判断相等。新审计表显式DEFAULT CHARACTER SET utf8mb4，避免继承库级窄字符集。现有utf8mb4表的排序规则不强制转换；不兼容旧表拒绝，由运维显式迁移，不自动ALTER或删除数据。

## 验证

新增2项顶层Go测试，总计105项：

- 真实MySQL构造7类异常表：主键前缀、租户索引前缀、序号/租户索引不可见、actor/resource为latin1、action为utf8mb3。分别验证只读预检查、正式迁移、v2启动、readiness、导出、空库恢复均拒绝；源状态保留、恢复不部分提交，SHOW CREATE TABLE不变。
- 将隔离测试库默认字符集改为latin1，验证显式创建的审计表仍完整存储中文/emoji主体、动作和资源，以及128个四字节字符的事件ID；执行迁移、导出和另一latin1默认空库恢复后校验全部值和三列实际字符集。

本地存储/API测试与编译结果记录在PR；本地未配置MySQL时数据库测试跳过，正式结论来自完整CI。CI继续竞态检测、真实MySQL/PostgreSQL、151组接口契约、运行/恢复/迁移及57项前端和浏览器回归。

## 边界

目标验证数据库为MySQL 8.4，使用其元数据属性，不宣称MariaDB/MySQL 5.7兼容。没有HTTP参数、前端或schema_version变化；未执行任何生产库ALTER。此项不是容量基准、完整约束审计或其他业务表/全局锁改造。
