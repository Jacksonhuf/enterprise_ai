# 第九轮：能力目录、分页与服务版本选择

日期：2026-11-16。基于已合并授权完整性改动的main（977dc3f）。

## 交付

- 服务发现代理转发既有v0.3的cursor/limit参数；资产与服务代理统一检查limit=1–100、query最多256字符、cursor最多2048字符。真实服务游标保持不透明，不由平台解析。
- 验证Mock的资产/服务目录按过滤和授权后的结果分页。Mock使用数值偏移游标，不能据此要求真实A–E也使用数值游标。
- 能力目录页使用服务端搜索、追加分页、加载/错误/重试状态，显示真实effective_version/service_version；服务详情用中文栏目展示输入参数，不再直接遍历全部JSON字段。
- 编辑器选择器完整读取目录页，并以“服务ID+版本”区分选项。切换版本只替换同一服务，其他引用保留；删除标签只移除对应引用。目录未返回的已有引用明确列出，只有用户移除才删除，能否发布仍由授权和引用检查决定。
- 后端草稿保存和发布检查禁止同一服务引用多个版本，避免运行时按服务ID选择第一条造成歧义。没有新增回滚、发布或运行接口。
- 分页列表收到401/403/404时清空已有结果并保留可追溯错误；目录详情随加载失败关闭。选择器加载失败不提交残缺结果，重复打开请求互斥。

## 验证

新增3项Go测试，合计53项：授权资产跨页遍历、服务不透明游标与limit转发、无效参数不触达上游、重复/冲突服务版本拒绝且草稿不变。

新增4项前端测试，合计20项：版本切换与其他引用保留、移除单项、缺失引用/版本冲突拒绝、不同版本跨页保留及权限错误清空。复用此前通用分页失败/竞态/重试用例。完整验收包括真实PostgreSQL、Go race、HTTP契约、三种存储编译程序运行验收，以及前端类型检查和构建，执行结果以对应提交CI为准。

多版本数据仅用于选择逻辑回归；实际验证服务仍只有replenishment-gap v1.1，不代表已提供v2业务执行。所有旧生产化与逐屏视觉验收待办保持，既有大包构建提示尚未解决。
