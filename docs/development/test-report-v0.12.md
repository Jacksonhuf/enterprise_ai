# 第十二轮：应用草稿与发布确认可靠性

日期：2026-11-16。基于已合并PR #7的main（29a3e37）。

## 交付

编辑器独立加载应用草稿与模型目录。应用加载失败明确展示错误和重试入口，不再无限加载；模型目录失败不会抹掉已有模型配置或阻止其他草稿编辑，目录缺失的当前模型显示原ID。合法的Go空切片/null列表规范化为可编辑空数组，缺少关键配置或版本时拒绝进入可写状态。

保存提交的是点击时的配置快照，带原草稿版本；保存期间的新输入不会被当作已保存。冲突保留输入，阻止盲目覆盖并提供显式重新加载。保存/检查/发布期间避免重复请求；同一路由切换应用与离开编辑器均检查未保存修改。请求返回后若编辑器已销毁，不再触发旧页面发布跳转。

发布检查绑定草稿版本、配置快照、当前发布指针与valid_until。检查期间发生新修改时丢弃结果；检查后修改、过期或版本变化时不能使用旧检查提交。前端时钟仅作提前拦截，服务端仍按自身版本和时钟判定。发布失败/结果未确认后清除本地检查，提示核对发布历史，不自动重提。发布完成时如果仍有新本地修改，留在编辑器，不把它们误标为已发布或已保存。

后端application.draft.save审计移入原Store事务，与草稿/版本一起提交，保留实际请求编号。原草稿、检查和发布接口参数不变；没有新增发布回滚或跨进程执行恢复接口。

## 验证

新增2项Go测试，合计66项：保存/冲突的版本及审计、已发布快照保持；两个真实PostgreSQL连接/API宿主同时保存同一版本，只有一个成功、另一个409，重开连接后仍只有一条成功保存审计，当前发布未被草稿修改。

新增9项前端测试，合计38项：加载失败/缺失数据与空列表、响应式快照克隆、重复保存抑制、保存中新编辑保留、冲突恢复、发布版本/配置/指针/截止时间绑定、检查过程中编辑、可修正的模型不可用错误、发布失败与晚响应、发布后新编辑保留、旧加载与已销毁编辑器隔离。继续执行类型检查和构建，以及真实PostgreSQL、Go race、内部HTTP契约与三种存储的编译程序运行验收。

## 边界

未实现多用户草稿自动合并；重载未保存输入前仍需用户明确选择。客户端无法把网络失败等同未发布，最终以服务端发布历史为准。模型目录降级不伪报模型可调用，发布与运行仍重新检查。逐屏视觉/导航验收、生产身份、生产数据模型与真实A–E/模型联调等既有待办保持。
