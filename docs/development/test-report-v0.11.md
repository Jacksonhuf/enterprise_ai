# 第十一轮：配置隔离、版本保护与个人资料同步

日期：2026-11-16。基于已合并PR #6的main（29a52f7）。

## 交付

配置按企业、个人/企业范围和分区使用独立存储键。旧公共配置仅向原企业42提供回读；旧个人配置按现有验证身份映射检查用户所属企业后回读，首次保存写入新命名空间，不删除旧键。状态增加可选setting_revisions映射，旧JSON/SQLite/PostgreSQL状态读取时初始化，不改动业务表DDL。

GET配置返回revision；PUT可携带expected_revision，在同一Store事务中校验版本、提交配置和审计。每次实际修改生成新版本，即使值改回原值也不复用旧版本，避免ABA覆盖。相同版本下保存相同已归档值不重复增加变更审计。旧客户端省略版本时仍可写入，但不获得并发覆盖保护；本产品表单始终携带版本。

表单加载失败或缺少版本时不能保存。版本冲突409保留输入并阻止直接重试；重新加载后再核对保存，离开、切换配置分区或重新加载未保存输入有提示。表单仅提交当前分区的可编辑字段，不将旧数据中的其他字段混入保存。

显示名称保存后通过/me刷新左下账户，清空后恢复身份来源名称。名称只作展示，不改变用户ID、企业、角色或数据范围；退出后，旧资料刷新响应不能重新填充账户。

## 接口

- GET /api/v1/cognitive/settings/{section}：原结构增加revision。
- PUT 同路径：原values之外增加可选expected_revision；返回values和revision；版本不匹配409 VERSION_INCOMPATIBLE。
- profile只允许display_name（最多80个字符，自动去首尾空格）；general只允许language（zh-CN/en-US）、timezone（明确IANA名称，拒绝Local）、density（comfortable/compact）；public只允许notice（最多512字符）。空字符串删除对应值，明确的空values对象可恢复默认记录。缺失/null values不被当作清空。
- public和其他管理分区仍需管理员；未接入提供方的分区只读，管理员写入503，非管理员403，未知分区404。
- /me结构不变，name可来自个人显示名称，其余身份和授权信息仍由认证来源提供。

## 测试

新增5项Go测试，合计64项：字段/枚举与权限、旧记录回读和隔离、版本冲突与ABA、JSON文件重开后的重复保存审计、显示名称和身份边界；两个真实PostgreSQL连接/API宿主同时提交相同初始版本，恰好一个成功、另一个409，JSONB回读后的等值保存不新增版本或审计，重开数据库后版本/配置/审计仍一致。

新增6项前端测试，合计29项：加载失败禁存、字段隔离、冲突保留、重复提交抑制、保存期间的新输入保留、旧请求/无版本响应、账户名称刷新与退出后旧响应隔离。沿用Go race、真实PostgreSQL、内部HTTP契约、三存储运行验收、类型检查和构建；最终通过状态见对应提交CI。

## 边界

本轮仅处理非敏感配置和资料一致性，不接入凭据、MCP等外部连接。语言与密度仍为偏好记录，不宣称全站本地化或样式切换已完成；公告仍为配置记录，没有全局分发。生产SSO、生产关系表/迁移、真实A–E联调及全量视觉验收保持待办。
