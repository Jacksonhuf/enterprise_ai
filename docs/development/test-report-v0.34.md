# 第三十四轮：MySQL异常状态定向更新

基线：PR #30已合并main，54f5eb7bb482572e8a6a9f6572d3482ba54148ed。部署方案保持不变。

## 实现

MySQL v2异常状态更新在状态行FOR UPDATE事务内，以JSON_TABLE遍历exceptions数组、按完整二进制字符串匹配tenant_id和id，只向Go返回第一个匹配的对象。JSON_TYPE要求两个身份字段为字符串，不将数字ID或带尾空格/不同大小写的ID视为相同，保留原Go循环的首匹配语义。

API读写共用原状态机：OPEN可确认或解决，ACKNOWLEDGED可解决，RESOLVED可重开；expected_revision不匹配或非法迁移返回409；不可访问记录404，非管理员403。成功时JSON_SET仅修改选中对象status/revision/updated_at/updated_by四个字段，并与审计关系表追加同事务提交。事务内重新读取实际JSON作为响应，未知属性及大整数不经过float64转换；其他数组元素和业务域不重新序列化。

v1、其他适配和相关audit/exceptions顶层大小写别名在回调前回退原路径。没有HTTP参数、表结构或schema_version变化。不获取Store.mu，但仍锁定现有数据库状态行；JSON_TABLE仍扫描数组，不宣称索引查询或无锁横向扩展。

## 验证

新增4项顶层Go测试，总计119项：

- 定向更新作用域与未知大整数保留；回调失败、重复审计及在审计INSERT后强制状态UPDATE失败均整笔回滚；跨租户不存在、取消请求不执行回调。
- 数字ID与字符串ID、大小写、尾空格、租户尾空格及重复ID按原首匹配语义处理；旧顶层别名回退。
- 真实HTTP v1/v2确认→解决→重开，过期版本/非法迁移409、非管理员403、跨租户404、成功更新审计次数；v2完整响应和其他域未知嵌套值精度保留。
- 双宿主相同expected_revision同时提交不同合法目标状态，仅一个200、另一个409，仅一次成功状态审计。

本地存储/API包测试通过，未配置MySQL时真实数据库用例跳过。正式结论以PR最新完整CI为准；继续运行竞态检测、真实数据库、接口契约、运行/恢复/迁移命令、57项前端与浏览器回归。

## 边界

异常仍存于状态JSON数组，新增能力是定向仓储而不是独立关系表。其他业务表、数据库行锁拆分、全量生产联调和身份集成仍待完成，未新增部署方案或性能基准承诺。
