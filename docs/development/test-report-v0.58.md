# 第58轮：R05-B根域业务入口schema3适配

基线PR55。第57轮的根域writer此前只供内部直接调用。本轮把现有业务写入入口在schema3下接到关系/根路径，HTTP处理函数无需修改：

- 通用`Store.Update*`：在MySQL上先锁定State行读取版本，schema3时在同一事务内走根域事务（关系读取器重建、回调、只写回根域、审计按序追加或不可变追加、提交前再次重组校验）。回调改动应用或检查即返回专用错误；应用/检查的HTTP入口接专用关系writer留待下一轮。
- 设置定向writer、异常状态定向writer、审计/失败异常追加writer：允许schema3，写入前经关系读取器做完整性校验，大小写别名歧义直接报错而非回退通用路径，提交前再次重组校验。原JSON路径定向更新方式不变。
- 根写回精度与扩展保真：类型化State解码会将大整数取整并丢弃未知键。写回时对比回调前后视图，未变子树保留库内原文；对象逐键合并并保留类型视图之外的键；数组元素仅当与后续旧元素相等时复用原文，删除不会把某元素的未知字段并到相邻元素，变更元素取新值。

真实MySQL 8.4专项（本地8.4.9实例）：通用业务/完整模式写入会话与审计、完整模式可见历史；通用入口改应用被拒；设置新键写入后可读回且带revision；异常状态迁移保留嵌套大整数、外租户不可选；失败异常追加；五类写入的审计顺序正确，应用投影不变，根无apps键，根扩展与异常精度保留。会话改标题后未知字段保留；删除异常首元素不串字段、不丢精度；未改动用量保持原文。通用、设置、失败追加与专用草稿writer四路并发全部提交无丢失。审计触发器故障时四类入口均整体回滚；关系布局损坏时四类入口均拒绝且不调用回调、不写审计；OpenMySQL仍拒绝schema3。变异验证六项均被捕获：取消schema3路由、取消原文合并、对象合并丢未知键、数组仅同下标匹配、异常writer不做schema3完整性校验、设置writer仍拒绝schema3锁定写入。

边界：变更后的类型化数组元素（如授权）仍按类型视图写入；数组含重复相同元素时原文复用可能前移，仅影响保真程度不影响值正确性。根写入每次完整重组校验，性能另验收。启动仍拒绝schema3，未开放外部激活；应用入口切换、C无损快照与D显式apply未完成，R05-B保持开发中。完整CI见PR。
