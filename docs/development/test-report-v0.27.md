# 第二十七轮：个人时区展示

基线：PR #23已合并main，65dbbbd047eb0fff2d471d5978e922db5b6bb162。

## 行为

沿用settings/general中的timezone，随个人偏好在登录、保存后读取，沿用已实现的账户和请求代次隔离，退出清除。应用列表更新时间、发布列表/详情时间、发布检查截止时间、聊天消息时间、治理采样时间及审计/用量发生时间使用统一Intl格式化，并展示该时点的GMT偏移量。字段清空、未知或浏览器不支持的时区使用浏览器默认时区，非法或缺失时间显示占位符。

夏令时按事件时点计算；不改变后端UTC时间、原始时间戳、检查有效期判断、时间筛选参数、游标和证据数据。TDesign日期范围控件仍使用浏览器本地时间，旁边明确标出浏览器时区；没有将该控件误称为支持个人时区输入。语言偏好仍只保存，通用偏好页说明已更新。

## 验证

新增5项日期格式化测试，覆盖跨日、冬夏令时、同一时点不同偏移表示、半小时时区、聊天时间与偏移、未知时区和非法时间回退。已有账户测试补充时区读取、退出和响应失败保留断言。前端测试合计57项；完整本地检查和CI结果见本PR。

浏览器固定UTC环境，在真实表单保存America/New_York并刷新，然后检查应用列表原始datetime所对应的纽约显示时间，验证设置覆盖浏览器时区；保留上一轮密度、换账号隔离、13条路由和聊天业务回归。完整CI仍复跑95项Go测试、真实数据库、API契约、运行及恢复验证。

## 边界

未新增HTTP接口或数据库迁移；不实现全量国际化、日期筛选控件的任意时区编辑、跨标签页实时同步或全量Figma视觉验收。Intl使用运行环境的时区数据库，可能与后端时区库版本不同；不支持的区域明确回退浏览器时区。
